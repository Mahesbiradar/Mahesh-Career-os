# Section 3 — Integrated mini-project

## Order Import and Audit Service

30 marks

Suggested filename: `order_audit_service.py`

This is the main practical component. Build a small service that imports order data, validates it, records an audit trail, and produces reports.

### Scenario

A backend application receives an order CSV every day. Some rows may be invalid, amounts may contain malformed values, timestamps may have different UTC offsets, and the input file may be missing or incomplete.

Your task is to create a reliable import pipeline.

### Functional requirements

### 1. Configuration and startup

- Read settings from JSON.
- Validate the required configuration keys and their types.
- Use `os` to resolve paths and create output directories.
- Use `sys` to support command-line execution and appropriate exit codes.
  ### 2. Data ingestion and validation
- Read CSV records using `csv.DictReader`.
- Validate the CSV headers and required fields.
- Validate order IDs using `re`.
- Validate amounts as finite, non-negative numbers.
- Parse timestamps and normalize valid aware timestamps to UTC.
- Reject invalid rows without aborting the entire import.
  ### 3. Processing and analytics
- Use `collections.Counter` for status and rejection-reason counts.
- Calculate total and average accepted amounts.
- Generate a reproducible test sample using `random`.
- Keep the accepted and rejected records separate.
  ### 4. Reports and audit trail
- Export accepted orders to CSV.
- Export rejected orders to CSV, including a rejection reason.
- Export a JSON summary containing counts, totals, and a UTC generation timestamp.
- Use `logging` for startup, accepted/rejected records, and fatal errors.
- Do not log sensitive information unnecessarily.

### Required input files

Create a JSON configuration file and a CSV input file of your own. Include at least 15 order rows, covering:

- Valid orders with different statuses.
- A negative amount.
- A non-numeric amount.
- A missing required field.
- An invalid order ID.
- A malformed timestamp.
- A timestamp without timezone information.
- A status that is not allowed.

### Required deliverables

1. `order_audit_service.py`
2. `config.json`
3. `orders.csv`
4. `accepted_orders.csv`
5. `rejected_orders.csv`
6. `summary.json`
7. A log file generated by your program.

The output files should be generated by your code; don't manually prepare the expected reports.

### Acceptance criteria

- One invalid row does not stop valid rows from being processed.
- Every rejected row has a meaningful reason.
- Summary counts agree with the exported records.
- Invalid configuration and missing input files are handled safely.
- Re-running with the same random seed reproduces the random sample.
- The program produces a consistent, auditable result.
